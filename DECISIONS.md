## 2026-10-29 — Milestone 7: battles

| #   | Decision                                                                                                                                      | Reason                                                                                                   |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| B1  | One combat engine in `@nyrgo/shared`, pure and deterministic; the server runs it with a secret seed per battle and turn and stores every turn | One set of rules, replayable for disputes, nothing to trust on the client                                |
| B2  | Damage = power × atk/def × 0.13 × (1 + level/25) × type^0.5 × 1.2 same element × crit 1.5 (6 %) × 0.85–1                                      | Simulated at ~4.5–5.5 turns between equal creatures at levels 5–40                                       |
| B3  | The type chart keeps ×2 / ×0.5 but battles apply its square root (×1.41 / ×0.71)                                                              | At full strength a 1v1 without switching was decided by type alone (99–100 %); now ~8 levels overturn it |
| B4  | Battles are a way to wear a wild creature down, not to defeat it: a win leaves it at 0 HP and up to twice as easy to capture                  | Fits "storing in a vault"; combat and capture reinforce each other                                       |
| B5  | One rewarded win per encounter; player reward 150 XP and 25 Gold up to 20 wins per day; the creature always gains 20 + 6 × foe level XP       | No farming one spawn; levelling still works after the cap                                                |
| B6  | Owned creatures keep their HP between battles and recover 10 % of max HP every 5 minutes, even from 0; patches heal in and out of battle      | Nobody gets stuck without a shop                                                                         |
| B7  | Creature XP curve 20·L·(L−1), max level 50; a level-up raises current HP by the growth of max HP                                              | Simple, tunable later                                                                                    |
| B8  | The wild creature fights with middle individual values (7) and picks its best move 70 % of the time                                           | Predictable enough to plan, not trivial                                                                  |
| B9  | Every passive's effect is implemented; stat passives name their stat in content (`stat`)                                                      | Content and rules can no longer drift                                                                    |

## 2026-10-29 — Milestone 6: spawns, encounters and captures

| #   | Decision                                                                                                                                                                      | Reason                                                                   |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| S1  | Spawns are generated per H3 r9 cell and 15-minute window from HMAC-SHA256(`SPAWN_SECRET`, cell, window); same for every player                                                | Fair, cheap (generated on first sight), unpredictable without the secret |
| S2  | Each cell refreshes at its own offset (hash of the cell id)                                                                                                                   | The map never changes all at once                                        |
| S3  | Cell biome = most common biome of its POIs (urban if none); slots per cell: urban 1, park 3, historic 2, culture 2, each filled 60 %                                          | More creatures in parks and old town, fewer on plain streets             |
| S4  | Wild rarity weights 62 / 25 / 10 / 3 (common to epic; v2: 64 / 26 / 8 / 2); level range by stage 2–10, 10–22, 22–35                                                           | Starting assumptions, to tune in the simulation (Phase 2)                |
| S5  | A candidate is dropped if it lands outside its cell or in any exclusion zone (water included)                                                                                 | Safety first; an empty slot is the cost                                  |
| S6  | "Seen" means an encounter was opened (within 40 m), not merely shown on the map                                                                                               | Seeing must take a walk; matches the Dex rule "hide until seen"          |
| S7  | The capture roll and chance are computed on the server; the client sends the vault and a timing score 0–1 worth at most +25 %                                                 | Client-reported skill is untrusted, so its weight is capped              |
| S8  | Capture requests need an `Idempotency-Key`; replays return the stored result, a different body with the same key is refused                                                   | A retried throw never spends two vaults or rolls twice                   |
| S9  | After a failed throw the creature may flee (10–35 % by rarity); a caught or fled spawn disappears for that player only                                                        | Tension per throw; other players are unaffected                          |
| S10 | Starter kit (15 basic vaults, 3 patches) granted once, on first need; one starter creature per player, picked from the three starters                                         | Playable from minute one without a shop                                  |
| S11 | Player levels: total XP 50·L·(L−1), max 50; level-up pays 20 Gold × new level (v2: 5 ×); all gameplay Gold counts against the daily cap of 1500 (v2: 500) (Europe/Madrid day) | Simple curve to tune later; one cap for every faucet                     |
| S12 | Spawns are kept 90 days after expiry, then deleted with their encounters and capture attempts                                                                                 | Enough history for support and anti-cheat review                         |

## 2026-10-29 — Milestone 4: movement checks, risk and retention

| #   | Decision                                                                                                                                                                                                              | Reason                                                                                          |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| M1  | Speed is computed from server receive times, never the client timestamp                                                                                                                                               | A client can send any timestamp it likes                                                        |
| M2  | Distance counts only beyond both accuracy radii (`certainM`)                                                                                                                                                          | GPS drift while standing still must not look like movement                                      |
| M3  | Above 30 km/h interactions pause, with no signal and no risk                                                                                                                                                          | Driving or riding is legitimate travel; the game just must not reward it                        |
| M4  | A jump (≥ 500 m at > 150 km/h) pauses interactions for 5 minutes and records a weak signal (15); above 1,200 km/h and ≥ 2 km the signal weighs 30                                                                     | Trains, tunnels and GPS reacquiring cause honest jumps; only repeated or impossible ones matter |
| M5  | Other weak signals: client clock off by > 2 min (3), 20 identical accuracy values ≤ 10 m (5)                                                                                                                          | Typical of mock-location apps, but never conclusive alone                                       |
| M6  | Each signal kind is recorded at most once per hour per player                                                                                                                                                         | One glitchy minute must not pile up score                                                       |
| M7  | Risk score = signals halving every 72 h, capped at 100; recomputed on each signal and nightly                                                                                                                         | Old mistakes fade                                                                               |
| M8  | At 70 a review case opens for a human; nothing is ever suspended automatically                                                                                                                                        | Master prompt §16: no bans on a single anomaly; appeals possible                                |
| M9  | `requireInteractable()` (fresh fix < 60 s, walking pace, no cooldown) guards every future gameplay action                                                                                                             | One rule for captures, POI rewards and battles                                                  |
| M10 | Fixes are serialized per player with an advisory lock                                                                                                                                                                 | Two parallel requests cannot both compare against the same previous fix                         |
| M11 | Jobs run on pg-boss inside the API process (`JOBS_ENABLED`); retention hourly at :07, risk decay daily at 03:17 UTC                                                                                                   | No extra service; pg-boss runs each cron once across processes                                  |
| M12 | Retention: exact positions nulled at 24 h (H3 cell kept), samples deleted at 30 days, risk signals at 90 days, expired sessions 7 days after expiry or revocation, used links after 1 day, idempotency keys at expiry | Commitments shown to players; deletes are batched                                               |
| M13 | Account erasure also deletes movement state, review cases and POI reports                                                                                                                                             | Nothing anti-cheat related survives a deletion request                                          |

## 2026-10-29 — Milestone 3: map and world data

| #   | Decision                                                                                                                                                                                                                                                | Reason                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| W1  | World data comes from an Overpass `out geom` query for a bounding box (Córdoba: 37.85,-4.85 → 37.92,-4.72)                                                                                                                                              | A box is unambiguous; a name lookup could pick Córdoba, Argentina                                   |
| W2  | Tag classification is a pure function with unit tests; PostGIS builds polygons (`ST_BuildArea`, `ST_MakeValid`) and buffers corridors                                                                                                                   | Rules are reviewable in one file; geometry handling stays in the database that is built for it      |
| W3  | Exclusion zones: schools, kindergartens, childcare, hospitals, clinics, police, prisons, fire stations, military, cemeteries, construction, rail land, reservoirs, playgrounds, water; motorways ±25 m, rail ±15 m; private homes; private-access areas | Master prompt §4 safety rules                                                                       |
| W4  | Places of worship are never POIs, even when tagged as attractions                                                                                                                                                                                       | Respect for worshippers; avoids a known problem of earlier location games                           |
| W5  | POIs ignore water zones (bridges stay visible); spawns will use every zone                                                                                                                                                                              | The Roman bridge sits over the Guadalquivir polygon                                                 |
| W6  | POIs are keyed by `n123` / `w123` / `r123`                                                                                                                                                                                                              | Nodes and ways can share numeric ids                                                                |
| W7  | Re-imports update in place, remove rows that vanished upstream, and keep hidden flags and report counts; seed and admin rows are never touched                                                                                                          | Imports must be safe to repeat                                                                      |
| W8  | Three distinct player reports hide a POI pending review                                                                                                                                                                                                 | Simple, abuse-resistant start; review queue comes with the admin dashboard                          |
| W9  | Client skips server calls for fixes worse than 50 m and re-queries after 25 m or 15 s (never within 3 s)                                                                                                                                                | Same threshold as the server; stays under the 30/min limit                                          |
| W10 | Without a PMTiles basemap the style is a plain background and makes no font or sprite requests                                                                                                                                                          | No third-party request at all in the default setup                                                  |
| W11 | MapLibre's worker URL is passed explicitly (`setWorkerUrl` + `?url` import)                                                                                                                                                                             | MapLibre builds the URL at runtime, which Vite cannot follow; verified in dev and production builds |
| W12 | Dev builds use the GPS simulator unless `?realgps` is in the URL; production bundles do not contain it                                                                                                                                                  | Testing without walking, verified by grepping the production bundle                                 |

## 2026-10-29 — Milestone 2: accounts

| #   | Decision                                                                                                                                     | Reason                                                                                                 |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| A1  | New accounts are only created as guests (age gate there); email is added later by upgrading                                                  | One place for the age check, and the magic-link endpoint never reveals whether an email has an account |
| A2  | Age gate asks birth month and year, stores only the band (`13-15`, `16-17`, `18+`)                                                           | Data minimization; month is enough to never overstate age                                              |
| A3  | Minimum age 14 for Spain, 16 elsewhere (GDPR default), per region                                                                            | LOPDGDD art. 7; to be reviewed per market                                                              |
| A4  | Sessions: 256-bit random token in an httpOnly, SameSite=Lax cookie; only the SHA-256 hash is stored; 30-day expiry; rotated on every sign-in | Stolen database rows cannot be replayed as sessions                                                    |
| A5  | Magic links: single use, 15 minutes, max 3 per address per 15 minutes, plus per-IP limits                                                    | Limits abuse of the email endpoint                                                                     |
| A6  | State-changing requests with a foreign `Origin` are refused                                                                                  | CSRF defence in addition to SameSite cookies                                                           |
| A7  | Unknown request fields are rejected (`removeAdditional: false`), not silently dropped                                                        | Fastify's default would hide client bugs and probing                                                   |
| A8  | Deleting a registered account needs a sign-in from the last 15 minutes                                                                       | Protects against a borrowed unlocked phone                                                             |
| A9  | Mail drivers: `log` (dev, prints the link) and `memory` (tests). The API refuses to start in production until a real provider is added       | Owner has no provider yet; never send sign-in links to logs in production                              |

## 2026-10-29 — Phase 1 architecture (approved by the owner)

| #   | Decision                                                                                                                         | Reason                                                                                |
| --- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| D1  | Modular monolith, pnpm monorepo (`apps/web`, `apps/api`, `packages/shared`)                                                      | Lowest operating cost at this stage; modules extract later if justified               |
| D2  | Map tiles: self-hosted Protomaps PMTiles from OSM data                                                                           | Fixed cost, no player locations sent to a third party (GDPR)                          |
| D3  | Spawns on H3 resolution 9 (~0.11 km² per cell in Córdoba, measured), regions on resolution 7                                     | Uniform hexagons; native PostgreSQL support through h3-pg                             |
| D4  | Creatures are painted 2D portraits (WebP) supplied by the owner; was code-drawn SVG, and 3D (GLB) before that, all on 2026-10-29 | Owner decision; no 3D engine to download                                              |
| D5  | Turn-based 1v1 PvE combat resolved on the server                                                                                 | Cheaper and harder to cheat than real time                                            |
| D6  | Login: guest + email magic link; OAuth later                                                                                     | Minimum personal data, no passwords to store                                          |
| D7  | Wallet (Phase 3): `@hot-labs/near-connect` + `near-api-js`                                                                       | The connector recommended by the official NEAR wallet-login guide, checked 2026-10-29 |
| D8  | Hosting: one EU server with Docker Compose, static frontend behind a CDN                                                         | EU data residency; provider and domain still to be chosen                             |
| D9  | Repo codename `nyrgo`; pilot city Córdoba, Spain                                                                                 | Owner choice                                                                          |

## 2026-10-29 — Implementation choices made while scaffolding

| #   | Decision                                                                                              | Reason                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| I1  | TypeScript pinned to `~6.0.3`, not 7.0                                                                | `typescript-eslint` 8.72 rejects TS 7 (peer range `<6.1.0`). Revisit when it supports 7 |
| I2  | Fastify 5 + TypeBox 0.34 for env and request validation                                               | Same schemas will generate the OpenAPI spec                                             |
| I3  | `node-pg-migrate` 9 with plain `.sql` migrations                                                      | Reviewable SQL, up/down in one file                                                     |
| I4  | PostgreSQL 17 image (`postgis/postgis:17-3.5` + `postgresql-17-h3`) for dev and CI                    | CI builds the same image as local dev, so both run identical extensions                 |
| I5  | Added a `config_versions` table (20 tables, not 19)                                                   | The master prompt requires versioned, auditable config                                  |
| I6  | `gold_ledger` and `admin_audit_log` are append-only via triggers, not only role grants                | Holds even when connected as a superuser                                                |
| I7  | GDPR erasure anonymizes the `users` row instead of deleting it                                        | Append-only ledgers keep only a pseudonymous id; personal fields are nulled             |
| I8  | Only one _successful_ capture per player and spawn (partial unique index); failed attempts may repeat | Lets players retry with another item while blocking duplicate rewards                   |
| I9  | `/health` never touches the database; `/ready` checks the database and spatial extensions             | Liveness must not flap when the database is slow                                        |
| I10 | Dev routes (`/dev/v1/*`) refuse to start in production                                                | Prevents the GPS simulator from ever reaching players                                   |
